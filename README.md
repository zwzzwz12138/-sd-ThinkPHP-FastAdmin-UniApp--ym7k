总部定价与门店定价双模式——连锁茶饮价格体系的技术实现
摘要：本文阐述连锁茶饮点餐系统中总部定价与门店定价双模式的设计与实现，涵盖价格模型、权限控制与价格同步机制。

一、双定价模式的业务背景
连锁茶饮品牌在不同城市、不同商圈的租金和竞争环境差异巨大。一点点、奈雪、喜茶等品牌在核心商圈和社区门店的定价策略往往不同。系统必须支持总部定价和门店定价两种模式：总部定价确保品牌价格体系统一，门店定价赋予门店灵活应对本地市场的能力。

二、价格模型设计
商品价格表采用“基础价格+门店价格覆盖”设计。总部商品库中存储标准价格（base_price），门店商品关联表中存储门店实际售价（store_price）和是否启用独立定价（price_mode）。当price_mode为总部定价时，store_price自动同步base_price；当price_mode为门店定价时，store_price由门店在总部允许的范围内自主设置。总部可设置价格浮动上限和下限，防止门店恶意低价或高价。

三、权限控制与操作流程
总部管理员可在后台批量设置商品的基础价格，并一键同步到所有选择总部定价的门店。门店店长登录门店独立后台后，可查看本店商品列表，对启用门店定价的商品进行价格调整。调整时系统校验是否超出总部设定的价格区间，超出则拒绝保存并提示。所有价格变更记录操作日志，便于总部审计。

四、价格缓存与实时同步
茶饮点餐对价格实时性要求高。系统使用Redis缓存商品价格，缓存键按门店ID和商品ID组合设计。总部修改基础价格后，通过消息队列通知各门店缓存失效；门店修改价格后，立即更新本店缓存。下单时，后端从数据库读取最新价格进行校验，防止前端篡改价格。

五、营销活动与价格叠加
优惠券、满减、第二件打折等营销活动与价格体系紧密相关。系统设计营销规则引擎，支持活动价与门店定价的叠加计算。总部发起的统一活动优先于门店自主活动，门店活动需在总部允许的范围内创建。支付时，系统按优先级依次计算优惠，确保价格计算准确。

六、小结
总部定价与门店定价双模式，是连锁茶饮系统平衡品牌统一性与门店灵活性的关键设计。合理的价格模型、严格的权限控制和高效的缓存同步，共同保障了价格体系的准确与稳定。
